## Task A — Sinkronisasi Tenant (Backend + Frontend)

### Backend: `app/Console/Commands/SyncTenants.php`

Diulis ulang mengikuti pola opti-works yang lebih robust:

| Fitur | Deskripsi |
|-------|-----------|
| **Pagination** | `PER_PAGE = 100`, `MAX_PAGES = 100` — ambil semua halaman, tidak ada infinite loop |
| **Deactivate missing** | Tenant ada di DB tapi tidak di API → `is_active=false`, `deactivated_at` diisi |
| **Reactivate returning** | Tenant muncul lagi di API → `is_active=true`, `deactivated_at` dihapus |
| **Field validation** | Lewati company yang hilang `id`/`name`/`code` dengan peringatan log |
| **Structured logging** | Output jumlah created/updated/deactivated/reactivated |

### Controller: `app/Http/Controllers/TenantController.php`

Method `sync()` sekarang:
- Memanggil `Artisan::call('app:sync-tenants')` (tidak lagi inline HTTP)
- Mengembalikan Inertia JSON dengan prop `syncResult`: `{ created, updated, deactivated, reactivated, total, success }`
- Mengembalikan prop `syncError` saat gagal
- Selalu mengembalikan `Inertia\Response` (tidak ada campuran redirect)

### Frontend: `resources/js/pages/tenants/Index.tsx`

Diulis ulang untuk menampilkan hasil sinkronisasi:

| Fitur | Deskripsi |
|-------|-----------|
| **Sync result toast** | Sonner toast dengan breakdown created/updated/deactivated/reactivated |
| **Sync error alert** | Alert inline saat sinkronisasi gagal |
| **Sync status** | Tombol sinkronisasi menampilkan status loading |
| **Wayfinder query params** | Menggunakan pola `tenantsIndex({ query: { search: value } }).url` |

### Tes (TDD)

`tests/Feature/Console/SyncTenantsTest.php` — 8 tes, semua lolos:
